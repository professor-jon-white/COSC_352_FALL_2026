## How this grade was reached

Go. Declares 2 real datasets but ships none; run.sh silently generates synthetic data in the real schema. Engine itself is excellent: full worker-pool concurrency, 15/15 architecture, tests, race-clean, verified by grader on real files. 5/5 cross-dataset questions with named stakeholders and ASCII charts. Graded down for absent data.

### Datasets identified
- NIBRS Group A / Part 1 Crime Data (data/crime.csv, NOT bundled; user must download)
- 311 Customer Service Requests 2024 (data/311.csv, NOT bundled; user must download)
- synthetic fallback: data/sample/crime_sample.csv + 311_sample.csv generated by cmd/gensample

### Concurrency primitives found
goroutines; generic Load[T] pipeline with single reader -> bounded batch channel (workers*2) -> NumCPU parser workers -> collector; sync.WaitGroup; sync/atomic counters; sync.Map interner; atomic layout cache; lock-free map-reduce join with per-worker private maps merged after wg.Wait (BuildContext); five questions run concurrently writing to distinct slice indexes (RunAll)

### Design patterns found
Pipeline (ingest.Load), Strategy (RowParser[T], Question, Renderer), Factory (NewQuestion, NewRenderer), Builder (report.Builder); generics; all realized in code

### Questions answered
1. Where is combined public-safety (Part 1 crime) and 311 service burden highest, and how concentrated is it? (Mayor's Office)
2. Does 311 demand track crime, and which high-crime neighborhoods file unusually few 311 requests per crime? (Office of Neighborhood Engagement)
3. How do crime and 311 intake vary by hour of day, and do the peaks line up for staffing? (BPD & DOT)
4. Do neighborhoods with more blight-related 311 requests experience more Part 1 crime? (Planning / HCD)
5. Do high-crime neighborhoods wait longer for 311 requests to be closed? (DPW / Office of Equity)

Stakeholders named: Mayor's Office, Mayor's Office of Neighborhood Engagement, Baltimore Police Department, Department of Transportation, Department of Planning / Housing & Community Development, Department of Public Works / Office of Equity

### Overview
Well-structured Go module (cmd/engine, cmd/gensample, internal/{model,ingest,analysis,report}) with a generic channel pipeline for ingestion, a lock-free map-reduce neighborhood join, concurrent question execution, and a Builder/Strategy/Factory report layer rendering ASCII charts and Markdown. Memory design (string interning, bounded channels, explicit GC with MemStats reporting) is explicit and measured. Code is idiomatic, tested, and the README matches it closely; the glaring gap is that no data ships with it.

### Stakeholder value
The five questions are well framed for named agencies with findings, charts, tables and recommendations; on real data (verified with grader-supplied files) Q2's under-reporting ranking and Q5's resolution-time equity check are actionable, and Q4 quantifies the blight-crime association. Q3 is two single-dataset histograms rather than a join, and because the submission ships only a synthetic generator, the default run yields random-number 'findings' of no municipal value.

### Issues noted
- data/ is empty: no real Open Baltimore data bundled and no fetch script; README requires manual download
- run.sh automatically falls back to the synthetic generator, so the documented default run analyzes random data
- Q3 (hour-of-day peaks) compares two single-dataset histograms rather than joining them
- All records are materialized before the join (382 MB RSS on real 433 MB input) despite the 'memory stays flat' framing
- No tests for report renderers or the questions' numeric outputs
- Normalization by lead grader: rubric -3 applied because the synthetic generator is the default run.sh path (same treatment as Jessica Madu); real_data 5 -> 2, total 85 -> 82.
