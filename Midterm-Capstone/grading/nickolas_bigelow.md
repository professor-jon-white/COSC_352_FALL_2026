## Concurrency Analysis

Genuine, layered, and race-clean:
- Ingest across datasets: one goroutine per source + `sync.WaitGroup` (`pipeline.go:167-175`).
- Ingest within a file: reader goroutine -> bounded channel of 2,048-row batches (`workers*2`) -> N parser goroutines -> ordered collector (`csvstream.go:129-222`); sequence numbers restore file order; per-worker skip counters merged under a mutex once.
- Spatial indexes built in 3 goroutines (`join.go:46-69`); outlet neighborhood vote, outlet exposure, baseline exposure and crime-near-outlet flags via `ParallelFor` (index-partitioned writes, `parallel.go:49-69`, `join.go:74-125`).
- Neighborhood map-reduce via generic `ParallelReduce[T,A]` with private accumulators + merge (`parallel.go:13-45`, `join.go:173-226`); also used inside Q4 and Q5 (`q4_equity.go:62-148`, `q5_timing.go:38-68`).
- Five analyses run concurrently with `recover()` isolation (`analysis.go:36-55`).
- Fetcher: worker pool of HTTP POSTs + single CSV-writer goroutine, `context` cancellation (`fetch.go:191-273`).
- `model.Interner` with `RWMutex` double-checked insert (`model.go:40-65`); memory sampler with atomics (`pipeline.go:313-359`).
Race detector: clean on tests and on a full real-data run.
